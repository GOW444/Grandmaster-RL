\begin{abstract}
\textbf{Effective chess training depends on selecting puzzles that are challenging
but still learnable. Existing platforms such as Chess.com and Lichess typically use
single-number rating heuristics that do not explicitly optimize long-term curriculum
quality across tactical themes. We frame adaptive chess puzzle selection as a Markov
Decision Process (MDP), where an agent observes a simulated learner's overall rating,
per-theme skills, recent success rate, and recent puzzle difficulty, then selects a
tactical theme and target difficulty. The environment retrieves real puzzles from a
preprocessed Lichess puzzle dataset using per-theme KD-tree nearest-neighbour lookup.
We train Proximal Policy Optimization (PPO) and Soft Actor-Critic (SAC), and compare
them against Random, RatingMatch, and FixedProgression baselines. The main metric is
Learning Efficiency Index (LEI), which combines rating gain, success rate, and
difficulty consistency. PPO achieves the strongest overall evaluation LEI while
maintaining a high held-out success rate, making it the recommended final curriculum
policy.}
\end{abstract}

\section{Idea}

Chess puzzle training is a natural curriculum learning problem. A puzzle is useful
only if it is neither too easy nor impossibly difficult, and long-term improvement may
depend on the sequence of themes presented to the learner. Standard rating-match
systems choose puzzles near a player's current global rating, but this approach has
three limitations.

\begin{enumerate}[leftmargin=*,itemsep=1pt,topsep=2pt]
    \item \textbf{Single-number skill model.} A global rating hides tactical variation:
    a player can be strong at forks and weak at endgames.
    \item \textbf{Greedy, memoryless selection.} Each puzzle is chosen independently,
    without planning a full training sequence.
    \item \textbf{No explicit robustness test.} A good curriculum should transfer to
    learners whose fatigue or solve behavior differs from training assumptions.
\end{enumerate}

Grandmaster-RL addresses these limitations by modelling puzzle selection as a
sequential decision problem. The agent sees a state vector describing the learner and
selects both a tactical theme and a continuous target difficulty. This makes it
possible to optimize cumulative learning rather than immediate puzzle matching alone.

\section{Dataset Description}

We use a reduced version of the open-source Lichess puzzle database. Each puzzle
contains a FEN position, solution moves, Glicko-2 puzzle rating, rating deviation, and
space-separated theme tags. We filter the dataset to keep puzzles with rating
deviation at most 150 and rating in $[400,3000]$.

Each puzzle is assigned to one primary tactical theme:
\[
\Theta = \{\texttt{fork}, \texttt{pin}, \texttt{mate}, \texttt{endgame},
\texttt{skewer}, \texttt{discovery}\}.
\]
The continuous puzzle rating is not binned. For each theme, we build a one-dimensional
KD-tree over puzzle ratings, allowing the environment to retrieve the real puzzle
nearest to a target rating.

During implementation, we fixed an important theme-mapping issue. Lichess does not use
the literal tag \texttt{discovery}; discovery puzzles appear as \texttt{discoveredAttack}
and \texttt{discoveredCheck}. These tags are now mapped into the internal
\texttt{discovery} category.

\section{Environment}

The environment is implemented using Gymnasium. Each episode consists of $T=100$
puzzle attempts. The normalized observation is
\[
s_t=[\rho,\phi_1,\ldots,\phi_6,\bar{p},\bar{\delta}],
\]
where $\rho$ is overall rating, $\phi_i$ are per-theme skill estimates, $\bar{p}$ is
rolling success rate, and $\bar{\delta}$ is rolling mean difficulty.

The action is a two-dimensional vector:
\[
a_t=[k,d],
\]
where $k$ is a continuous theme value rounded to a valid theme index, and $d\in[0,1]$
is denormalized to a target puzzle rating in $[400,3000]$. The KD-tree for the chosen
theme returns the nearest real puzzle rating.

\subsection{Learner Dynamics}

Solve probability follows a logistic Item Response Theory style model:
\[
P(\text{solve}) =
\sigma\left(\frac{\phi_k-\delta}{\tau}\right),
\]
where $\phi_k$ is the learner's skill in the selected theme, $\delta$ is the puzzle
rating, and $\tau$ controls response smoothness.

After each attempt, the selected theme skill is updated as
\[
\text{gain}=
\begin{cases}
2\mu + \lambda\max(\delta-\phi,0), & \text{if solved},\\
-\mu, & \text{otherwise}.
\end{cases}
\]
\[
\phi_{\text{new}}=\text{clip}(\phi+\alpha\cdot\text{gain},400,3000).
\]
The reward is the change in overall learner rating after the update.

\section{Algorithms}

\subsection{PPO}

PPO is the primary algorithm. We use a custom actor-critic policy with a shared MLP
trunk and two actor heads: a categorical head for tactical theme selection and a
Gaussian head for continuous difficulty. This matches the hybrid structure of the
curriculum action.

\subsection{SAC}

SAC is included as a comparison method. Stable-Baselines3 SAC expects fully continuous
actions, so the SAC trainer uses the standard \texttt{MlpPolicy}. This is compatible
with the environment because the theme component is represented as a continuous float
and rounded at environment step time. SAC is therefore a useful aggressive
continuous-control comparison, but PPO is a cleaner fit for the mixed action semantics.

\subsection{Baselines}

We compare against three heuristic agents:

\begin{itemize}[leftmargin=*,itemsep=1pt,topsep=2pt]
    \item \textbf{Random}: selects theme and difficulty uniformly at random.
    \item \textbf{RatingMatch}: selects difficulty near the learner's current rating.
    \item \textbf{FixedProgression}: starts easy and increases difficulty on a schedule.
\end{itemize}

\section{Evaluation Metrics}

The main metric is the Learning Efficiency Index:
\[
\text{LEI}=
\frac{\Delta \rho}{T}\cdot \bar{p}\cdot
\frac{1}{1+\text{Var}(\delta)/\sigma^2_{\text{ref}}},
\]
where $\Delta\rho$ is episode rating gain, $\bar{p}$ is success rate, and the final
term rewards stable difficulty selection.

We also report mean rating gain, mean success rate, and robustness:
\[
\text{Robustness}=\frac{\text{LEI}_{\text{eval}}}{\text{LEI}_{\text{train}}+\epsilon}.
\]
The evaluation environment injects fatigue and IRT-temperature jitter that are not
seen during training.

\section{Experimental Setup}

Both PPO and SAC were trained for 500,000 timesteps with seed 42. PPO used
$n\_steps=2048$, batch size 256, 10 epochs per update, learning rate $3\times 10^{-4}$,
discount factor $\gamma=0.99$, and clipping range 0.2. SAC used replay buffer size
100,000, batch size 256, learning rate $3\times 10^{-4}$, automatic entropy tuning,
and one gradient step per environment step after 1,000 warm-up steps.

We also built a Streamlit dashboard for loading trained PPO/SAC checkpoints, running
multi-agent evaluation, and generating publication plots. The final repository
contains trained checkpoints, preprocessing scripts, evaluation utilities, tests, and
six generated plots.

PPO achieves the highest evaluation LEI, indicating the best overall balance of rating
gain, success rate, and difficulty consistency. Its held-out success rate is 69.7\%,
which suggests that it selects puzzles that are challenging but still solvable.

SAC obtains the largest raw rating gains, especially in the evaluation environment
($\Delta\rho=11.34$), but its success rate is only 13.3\%. This indicates a more
aggressive strategy: SAC chooses harder puzzles, producing large gains when solved but
many failures overall. Its lower robustness score suggests weaker transfer to unseen
learner dynamics.

RatingMatch and FixedProgression are competitive, which is expected because simple
difficulty matching is already a strong tutoring heuristic. PPO still outperforms both
on evaluation LEI, supporting the value of RL-based curriculum optimization.

\section{Conclusion}

Grandmaster-RL successfully implements an RL-based adaptive chess puzzle curriculum
using real puzzle metadata and simulated learner dynamics. PPO is the recommended final
policy because it gives the best evaluation LEI while maintaining a high solve rate and
reasonable robustness. SAC is useful as a high-risk, high-reward comparison model, but
its low success rate makes it less suitable as the main tutoring policy. Future work
includes true hybrid SAC with Gumbel-Softmax theme selection, richer learner models
trained from real interaction logs, and user studies measuring learning gains against
platform baselines.
